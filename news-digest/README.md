# 아침 뉴스 요약

매일 아침, 7개 주제별로 지정한 신문사·방송사 기사 가운데 **본문이 가장 긴 5건**씩을 골라 짧은 요약 페이지로 만듭니다. 주제는 페이지 위쪽 탭으로 나눠 봅니다.

- 보는 곳: https://fmlm66.github.io/survey-tally/news/ (지난 요약도 같은 페이지 아래에 있습니다)
- 주제: 국내정치, 세계정치, 산업경제, 금융증권, 사회, 문화, 과학기술
- 실행: GitHub Actions가 매일 06:40(한국 시각)에 돌립니다. GitHub 사정으로 몇 분~수십 분 늦을 수 있습니다. Actions 탭의 **news-digest daily** → **Run workflow**로 바로 돌릴 수도 있습니다.
- 외부 API·유료 서비스 없이 Python 표준 라이브러리만 씁니다.

## 고르는 방법

1. 주제마다 `config.json`에 적힌 언론사 분야별 RSS에서 최근 `window_hours`(24시간) 안의 기사를 모읍니다. 여러 주제 RSS에 같은 기사가 있으면 앞 주제에 둡니다.
2. 주제마다 최대 `max_fetch_per_topic`(60)건의 기사 페이지를 열어 **본문 글자 수(공백 제외)**를 셉니다. 언론사를 번갈아 가며 최신 기사부터 엽니다.
   - 페이지에 구조화 데이터(`articleBody`)가 있으면 그 길이를, 없으면 메뉴·광고·링크·사진 설명을 뺀 뒤 글자가 가장 많이 모인 부분의 길이를 씁니다.
   - 페이지를 열지 못하거나 본문을 찾지 못한 기사는 뺍니다.
3. 제목이 비슷한 기사는 같은 소식으로 묶고 본문이 가장 긴 기사를 대표로, 다른 언론사는 "같은 소식"으로 적습니다.
4. 본문이 긴 순서로 주제마다 `per_topic`(5)건.

요약은 언론사가 RSS(없으면 기사 페이지 소개문)에 실은 글의 앞 두 문장(최대 200자)이고, 기자 표기 등은 걷어 냅니다. 기사 본문은 글자 수만 세고 저장하거나 보여 주지 않으니, 전체 내용은 원문 링크에서 보세요.

## 주제·언론사 바꾸기

`config.json`을 고칩니다.

| 항목 | 뜻 |
| --- | --- |
| `title` | 페이지 제목 |
| `topics` | 주제 목록(탭 순서). 주제마다 `name`과 `feeds`(`source` 언론사 이름, `url` RSS 주소) |
| `per_topic` | 주제마다 보일 기사 수(기본 5) |
| `max_fetch_per_topic` | 주제마다 본문 길이를 잴 최대 기사 수(기본 60). 늘리면 정확해지지만 느려지고 언론사 사이트 부담이 커집니다 |
| `window_hours` | 최근 몇 시간 안의 기사만 볼지(기본 24) |
| `sources` | 언론사별 선택 설정. `"undated": "recent"`는 날짜를 싣지 않는 RSS의 기사를 최근 기사로 봅니다 |

RSS 주소를 바꾼 뒤에는 아래 점검을 돌려 기사와 본문이 읽히는지 확인하세요.

## 직접 돌리기·점검·시험

```bash
cd news-digest
```

```bash
python -m newsdigest --check-feeds
```

```bash
python -m newsdigest --out ../news --print
```

```bash
python -m unittest -v
```

- `--check-feeds`: 주제·언론사별로 RSS가 열리는지, 최근 기사 수, 첫 기사 페이지의 본문 글자 수를 표로 보여 줍니다.
- `--now 2026-11-18T16:30:00+09:00`: 기준 시각을 정해 만듭니다.
- `--dump 파일` / `--from-dump 파일`: 수집·측정 결과를 저장했다가 접속 없이 다시 만듭니다.
- GitHub Actions의 **news-digest test** 워크플로가 PR마다(또는 Run workflow로) 시험, RSS·본문 점검, 미리보기를 돌립니다.
