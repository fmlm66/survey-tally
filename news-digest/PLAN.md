# 아침 뉴스 요약 계획서

## 목표

매일 아침, 7개 주제별로 지정한 신문사·방송사에서 본문이 가장 긴 기사 5건씩을 골라 짧게 요약한 웹페이지를 만든다. 주제는 페이지 위쪽 탭으로 나눠 본다.

## 정한 것

| 항목 | 결정 |
| --- | --- |
| 주제(7개) | 국내정치, 세계정치, 산업경제, 금융증권, 사회, 문화, 과학기술 |
| 주제 분류 | 각 언론사의 **분야별 RSS**로 나눈다(키워드 판정 없음). 주제마다 어느 언론사의 어느 RSS를 쓸지 `config.json`에 적는다 |
| 고르는 기준 | 주제마다 **기사 본문 글자 수가 가장 긴 5건** |
| 받아 보는 곳 | GitHub Pages: `https://fmlm66.github.io/survey-tally/news/` |
| 실행 | GitHub Actions, 매일 06:40(한국 시각). 몇 분~수십 분 늦을 수 있음 |
| 요약 | 외부 API 없이 언론사가 싣는 요약문(RSS 요약문, 없으면 기사 페이지의 소개문)의 앞 두 문장 |
| 기존 설문 집계기 | 그대로 둔다 |
| 의존성 | Python 표준 라이브러리만 |

## 처리 순서

1. **수집**: 주제별로 설정된 RSS를 읽는다. 한 주소가 실패해도 나머지로 계속한다.
2. **기간**: 기준 시각 전 `window_hours`(기본 24) 안의 기사만. 날짜를 싣지 않는 RSS는 언론사 설정 `"undated": "recent"`로 최근 기사로 본다(기사 페이지에 발행 시각이 있으면 그것을 쓴다).
3. **중복**: 같은 주소는 하나로. 여러 주제 RSS에 같은 기사가 있으면 설정에서 앞선 주제에 둔다. 제목이 비슷한 기사(글자 2개 묶음이 짧은 제목 기준 45% 이상 겹침)는 같은 소식으로 묶는다.
4. **본문 길이 재기**: 주제마다 최대 `max_fetch_per_topic`(기본 60)건의 기사 페이지를 열어 본문 글자 수(공백 제외)를 센다. 언론사마다 번갈아 가며 최신 기사부터 고른다. 동시에 8건까지, 한 페이지 15초 제한.
   - 본문 찾기: 페이지에 구조화 데이터(JSON-LD `articleBody`)가 있으면 그 길이. 없으면 스크립트·메뉴·머리말·꼬리말·링크 글자를 뺀 뒤, 글자가 가장 많이 모인 블록(div·article·section)의 글자 수.
   - 페이지를 못 열거나 본문을 못 찾은 기사는 순위에서 뺀다.
5. **고르기**: 같은 소식 묶음마다 본문이 가장 긴 기사를 대표로 삼고, 대표의 본문 길이 순으로 주제마다 `per_topic`(기본 5)건. 묶음의 다른 언론사는 "같은 소식"으로 적는다.
6. **요약**: RSS 요약문(없으면 기사 페이지의 `og:description`)에서 기자 표기 등을 걷어 낸 앞 두 문장, 최대 200자. 기사 본문 자체는 저장하거나 보여 주지 않는다(글자 수만 센다).

## 결과 페이지

- 위쪽에 주제 탭 7개(각 탭에 기사 수). 스크립트 없이 CSS만으로 동작해, 외부·인라인 스크립트를 모두 막는 CSP를 유지한다. 키보드(화살표)로도 탭을 바꿀 수 있다.
- 기사마다 제목(원문 링크), 언론사·시각·본문 글자 수·같은 소식, 요약.
- `news/YYYY-MM-DD.html`(그날), `news/index.html`(최신 + 지난 목록). 휴대폰 화면·어두운 모드 지원.

## 점검

- `python -m newsdigest --check-feeds`: 주제·언론사별로 RSS가 열리는지, 최근 기사 수, 그리고 첫 기사 페이지에서 본문 글자 수가 읽히는지 표로 보고한다.
- 이 작업 환경에서는 언론사 접속이 막혀 있어, GitHub Actions(`news-digest test` 워크플로)에서 돌려 확인한다.

## 구조

```
news-digest/
  config.json            주제·RSS·개수
  newsdigest/
    feeds.py             RSS 읽기, 날짜
    article.py           기사 페이지에서 본문 글자 수·소개문·발행 시각 읽기
    selection.py         기간, 중복 묶기, 본문 길이 재기, 주제별 고르기
    summarize.py         요약문 다듬기
    render.py            탭 페이지 만들기
    dump.py              수집 결과 저장/복원(--dump / --from-dump)
    __main__.py          실행
  tests/
```

## 작업 순서(작업마다 커밋)

1. 계획서 갱신
2. 기사 페이지 본문 길이 읽기 + 시험
3. 주제별 수집·고르기(본문 길이 순) + 설정 파일 + 시험
4. 탭 페이지 + 저장/복원·점검 갱신 + 시험
5. README, CI 갱신 → GitHub Actions에서 RSS·본문 읽기 점검 → 안 되는 주소 정리
